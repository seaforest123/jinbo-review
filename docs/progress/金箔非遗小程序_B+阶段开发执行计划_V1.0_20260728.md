# 金箔非遗小程序 B+ 阶段开发执行计划

> 文档版本：V1.0\
> 制定日期：2026-07-28\
> 适用项目：金箔非遗数字体验与活化传播微信小程序\
> 当前决策：以原生微信小程序的 B+ 路线作为近期主线；方案 A 暂不进入正式开发，仅保留为后续独立验证方向。

## 1. 文档用途

本计划用于指导当前小程序从“功能可运行”推进到“普通用户能顺利完成、操作流畅自然、体验具有趣味、内容可正式展示”的阶段。

后续新增需求、安排开发工作和验收版本时，应优先参照本计划。若需求明显超出本计划范围，应先评估工期、包体、兼容性和对现有流程的影响，再决定是否进入当前版本。

## 2. 核心结论

近期不迁移 Cocos Creator，不把项目改造成微信小游戏。

当前项目已经是可运行的原生微信小程序，五道工序、共享金箔状态、入门辅助、完成上限、错误拦截和主要界面已经具备。下一阶段最有价值的工作不是更换技术框架，而是补齐以下三类体验：

1. 声音、触觉、动效和危险提示，让操作更有反馈、更像正常手机 App；
2. 真实照片、短视频和更统一的视觉素材，让内容更可信、更有展览感；
3. 真机测试与新手可用性修正，保证业余用户也能完整走完一次流程。

推荐执行节奏为 3～4 周；若照片、视频、音频和测试设备准备充分，并严格控制范围，可压缩到约 2 周。

## 3. 当前项目基线

### 3.1 已具备的能力

- 原生微信小程序工程可编译运行；
- 五道制作工序使用同一份金箔状态，前一步操作会影响后一步；
- 裁金片和装箔均限制为最多 3 片，达到上限后锁定；
- 裁剪不符合要求时不会直接判定合格，入门辅助仅在接近目标时生效；
- 锤击完成后默认锁定；从检查环节明确返回时，只允许一次返工；
- 检查扫描和最终抛光均有完成上限，避免无限操作；
- 新手辅助可以保证用户在提示下完成完整五步流程；
- 首页、体验页、主要标题和按钮已完成一轮居中、字号与层级优化；
- 已具备金箔厚度、覆盖、风险、瑕疵和完成质量的可视反馈；
- 已有短视频和帧动画的本地候选素材接入结构；
- 自动化测试当前为 203 项全部通过。

### 3.2 当前技术与包体状态

- 工程类型：微信小程序，不是微信小游戏；
- 当前包体审计结果：2,000,887 字节；
- 当前离线动画素材：344,388 字节；
- 当前离线视频素材：284,362 字节；
- 当前本地素材总数：25 个；
- 按项目现有 2 MiB 发布警戒线计算，只剩约 96,265 字节余量。

因此，后续真实照片、视频和音频原则上不得继续大量放入主包，应优先使用云存储或稳定 HTTPS CDN；必要时再使用分包。主包仅保留启动必需的图标、占位图、关键低体积动效和断网兜底素材。

## 4. 本阶段目标与非目标

### 4.1 阶段目标

完成本计划后，小程序应达到以下状态：

- 第一次使用的业余用户能看懂每一步要做什么；
- 用户操作错误时能及时知道“错在哪里、如何修正”；
- 每道工序达到数量或进度上限后立即锁定，不再继续累加；
- 五道工序都有可感知的声音、视觉或触觉反馈，不再显得单调；
- 页面切换、拖动、点击、扫描、敲击和完成反馈自然连贯；
- 真实照片和视频接入后不明显拖慢首屏和核心操作；
- 真机连续完成三次流程，不出现卡死、状态错乱或无法进入下一步；
- 形成可用于汇报和后续迭代的截图、录屏、测试记录及问题清单。

### 4.2 本阶段不做

- 不迁移 Cocos Creator；
- 不改造成微信小游戏；
- 不在当前版本建设完整 3D 场景或复杂物理引擎；
- 不为追求“游戏级效果”重写现有五步业务逻辑；
- 不一次性加入大量未经筛选、未经压缩的照片和视频；
- 不在专业内容尚未确认前，把候选说明写成确定性非遗事实；
- 不扩展新的大型功能模块，除非它直接解决流程完成率、展示效果或真机稳定性问题。

## 5. 总体优先级

| 优先级 | 工作项 | 原因 |
| --- | --- | --- |
| P0 | 新手可完成性、状态上限、错误提示、崩溃与卡死 | 决定用户能否使用 |
| P0 | 音频管理、锤击危险反馈、关键触觉反馈 | 直接改善趣味性和操作确认感 |
| P0 | 真机兼容与性能测试 | 开发者工具流畅不等于真实手机流畅 |
| P1 | 真实照片、短视频和统一视觉素材接入 | 提升真实性、展览感和汇报质量 |
| P1 | 五道工序动效与节奏细化 | 提升沉浸感，但不得破坏可完成性 |
| P2 | 分享海报、收集册和非核心页面精修 | 可在核心体验稳定后推进 |
| 暂缓 | Cocos、3D、复杂粒子和完整游戏化重构 | 当前投入产出比低，技术路线不同 |

## 6. 分阶段执行计划

### 阶段 0：冻结可运行基线

预计工期：0.5～1 个工作日。

#### 工作内容

- 保存当前可运行版本的测试结果和包体审计结果；
- 建立一份五步标准操作路径；
- 在至少一台真实手机上录制当前版本完整流程；
- 记录当前已知问题，不在后续修改中丢失已有正确行为；
- 将“203 项测试全部通过”和“包体审计通过”作为回归基线。

#### 验收标准

- `npm test` 全部通过；
- `npm run audit:assets` 通过；
- 五步流程可以完成；
- 当前版本录屏、关键页面截图和问题清单可查阅。

### 阶段 1：反馈系统与趣味性增强

预计工期：5～8 个工作日。

#### 6.1 统一音频管理

建立统一的音频管理模块，不允许各页面重复创建、无序播放音频实例。

建议音效分层：

- 页面与按钮：轻触、切换、确认；
- 裁剪：划切、接近目标、合格、超出范围；
- 装箔：放置、叠加、达到 3 张上限；
- 锤击：轻击、标准击、危险击、破损预警、完成一轮；
- 检查：扫描、发现瑕疵、允许返工、检查完成；
- 出箔：抛光、进度阶段变化、100% 完成、结果揭晓；
- 全流程：步骤完成和最终完成提示音。

实现要求：

- 遵守微信端首次用户操作后才能稳定播放声音的限制；
- 页面退出、隐藏或重进时停止或恢复正确的音频；
- 音频加载失败不得阻断五步流程；
- 同类高频音效应限制并发，避免锤击时声音叠成噪声；
- 提供总开关，并记住用户的静音选择；
- 背景音、环境音和操作音分开控制音量。

#### 6.2 触觉与视觉反馈

- 关键成功操作使用轻触觉反馈；
- 达到上限、危险敲击和最终完成使用不同强度或节奏；
- 不支持触觉的设备自动降级，不弹错误提示；
- 动效优先使用 `transform` 和 `opacity`，减少高频布局重排；
- 所有动画都不得遮挡操作目标或阻止用户继续；
- 低性能设备允许减少粒子、阴影和同时播放的动画数量。

#### 6.3 五道工序趣味性细化

**工序 1：裁金片**

- 清晰显示目标区域、当前裁片位置和差距；
- 裁错时给出方向性提示，而不是只显示“不合格”；
- 接近目标才触发吸附，新手不会因细小误差反复失败；
- 合格 3 片后出现“已备齐”反馈并锁定操作。

**工序 2：装箔**

- 每放入一张都显示堆叠高度、压合或层次变化；
- 第 3 张放入时给出明显的完成反馈；
- 放满后禁止继续放入，按钮、手势和状态逻辑同时锁定；
- 若顺序或位置不合适，提示如何调整。

**工序 3：打箔**

- 敲击加入节奏、力度和落点反馈；
- 危险区域必须在破损前明确预警，不能只在失败后告知；
- 使用颜色、轻微抖动、裂纹征兆和音效表达风险；
- 入门模式优先保护流程可完成性，专业模式再提高惩罚；
- 完成一轮后锁定；只有从检查页明确选择返工，才开放一次敲击。

**工序 4：检查**

- 扫描过程显示扫过范围、瑕疵位置和当前结论；
- 扫描完成后明确区分“可进入下一步”和“建议返工”；
- 返回返工时保留原有金箔状态，不重新开始；
- 扫描达到上限后锁定，避免重复扫描造成状态混乱。

**工序 5：出箔**

- 抛光过程展示表面变化、光泽和完成度；
- 25%、50%、75%、100% 设置清晰阶段反馈；
- 100% 后立即锁定，防止重复提交；
- 完成时展示前后对比、质量摘要和五步操作痕迹。

#### 阶段 1 验收标准

- 五道工序每一步至少有一种声音反馈和一种视觉反馈；
- 关键完成与危险状态有可区分的触觉或替代视觉反馈；
- 静音、页面切换、后台恢复和音频加载失败均不会阻断流程；
- 达到 3 片、1 次扫描或 100% 等上限后不能继续累加；
- 新手模式连续完成三次，不需要开发人员代操作；
- 自动化测试和包体审计继续通过。

### 阶段 2：真实媒体与视觉统一

预计工期：4～7 个工作日；从收到可用素材后开始计算。

#### 6.4 素材接收方式

用户可以先提供照片或视频链接用于筛选和确认，但正式接入前应满足以下任一方式：

1. 提供可长期访问的稳定 HTTPS 直链；
2. 提供原始文件，由项目统一压缩并上传到云存储或 CDN；
3. 提供网盘或临时下载链接，下载后转存到项目可控的存储位置。

不建议正式版本长期依赖聊天附件、临时分享链接、需要登录的网页地址或随时可能失效的第三方链接。

每份素材至少记录：

- 文件名或素材编号；
- 展示内容；
- 拍摄者或来源；
- 是否获得展示授权；
- 拍摄时间和地点（若适用）；
- 对应页面或工序；
- 是否允许裁剪、压缩和加字幕；
- 专业说明是否已经确认。

#### 6.5 图片与视频处理原则

图片：

- 原图保留在素材归档区；
- 小程序使用压缩后的 WebP、JPEG 或适合场景的 PNG；
- 首页首屏图、步骤图和缩略图使用不同尺寸，不用同一张超大图硬缩放；
- 加载失败时显示本地占位图；
- 非首屏图片使用懒加载。

视频：

- 优先使用短视频和明确的封面图；
- 编码、分辨率和码率以真机兼容与清晰度平衡为准；
- 视频默认不自动带声音播放，避免与背景音冲突；
- 首屏不预加载大视频；
- 网络较差时允许只显示封面和文字说明；
- 视频应上传到项目可控的云存储或稳定 CDN。

#### 6.6 视觉统一

- 统一标题、正文、说明、数据、按钮和状态标签的字号层级；
- 统一金色、墨色、米白和危险色的用途；
- 真实照片与数字交互区使用一致的圆角、边框和留白；
- 避免每个步骤使用完全不同的装饰风格；
- 优先提升信息层级和可读性，不以增加装饰数量作为美化标准；
- 所有主要页面适配系统胶囊区域、窄屏和常见全面屏。

#### 阶段 2 验收标准

- 所有正式素材均有来源和授权状态记录；
- 真实媒体使用稳定地址，临时链接不进入发布配置；
- 弱网或媒体加载失败时仍可完成五步流程；
- 首页首屏不因加载视频而长时间空白；
- 五步页面的字体、按钮、状态颜色和间距保持一致；
- 新增素材后包体审计仍通过。

### 阶段 3：真机测试、可用性修正与交付

预计工期：4～6 个工作日。

#### 6.7 测试设备

至少覆盖：

- 一台中低性能 Android 手机；
- 一台主流 Android 手机；
- 一台近年 iPhone；
- 微信开发者工具只用于辅助定位，不代替真机验收。

#### 6.8 必测场景

- 首次进入、再次进入和从后台恢复；
- 开启声音、静音和系统媒体音量较低；
- 正常网络、弱网、视频加载失败和短暂断网；
- 快速连续点击、重复手势、误触和中途退出；
- 五步正常完成、工序返工、查看提示和重试；
- 裁剪 3 片、装箔 3 张、敲击完成、检查完成、抛光 100% 后继续操作；
- 页面切换时音频、动画、定时器和状态是否正确释放；
- 不同屏幕宽度、系统字体设置和胶囊位置；
- 连续完成三轮，观察内存、发热、卡顿和状态污染。

#### 6.9 新手可用性测试

建议邀请 10 名没有项目背景、没有金箔制作经验的体验者。

记录：

- 是否能在不看开发说明的情况下开始；
- 卡住的步骤和停留时间；
- 请求提示的次数；
- 误操作次数；
- 是否需要旁人代操作；
- 是否成功完成五步；
- 对趣味性、真实感、清晰度和流畅度的主观评价。

阶段通过建议标准：

- 至少 8/10 名新手可在不由开发人员代操作的情况下完成；
- 没有人因为状态上限、按钮失效或流程死锁而无法继续；
- 连续三轮完整流程无崩溃、无数据串轮、无重复提交；
- 不存在阻断发布的 P0 问题和高频 P1 问题；
- 中低性能设备没有连续 300 毫秒以上、明显影响操作的卡顿；
- 媒体加载失败时核心制作流程仍可使用。

#### 6.10 交付物

- 可运行的小程序版本；
- 自动化测试报告；
- 包体审计结果；
- 真机测试设备与问题记录；
- 10 名新手体验结果摘要；
- 首页和五道工序的成套截图；
- 一段从首页进入到完成结果的完整录屏；
- 一段 30～60 秒的精简演示视频；
- 已知限制与下一版建议；
- 素材来源、授权与存储位置清单。

## 7. 推荐排期

以下以启动日 T0 计算，便于以后从任意日期开始执行。

| 周期 | 主要工作 | 里程碑 |
| --- | --- | --- |
| T0～T0+1 天 | 冻结基线、真机录屏、问题清单 | M0：现状可追溯 |
| 第 1 周 | 音频管理、基础音效、触觉、锤击危险反馈 | M1：核心操作有反馈 |
| 第 2 周 | 五步动效和节奏细化、状态回归 | M2：完整流程更有趣且仍可完成 |
| 第 3 周 | 真实图片/视频接入、视觉统一、弱网降级 | M3：展示内容达到汇报质量 |
| 第 4 周 | 多机型测试、新手测试、修复、截图与录屏 | M4：形成可交付版本 |

若素材未按时到位，阶段 2 延后，但阶段 1 和阶段 3 的纯交互测试部分继续推进。不得为等待素材而停止稳定性与新手体验工作。

## 8. 每次迭代的完成定义

一项功能只有同时满足以下条件，才标记为“完成”：

- 功能行为与本计划一致；
- 正常路径、错误路径和重复操作都已验证；
- 新手模式能继续完成流程；
- 不破坏数量上限和状态锁定；
- 页面退出或重进后状态符合设计；
- 低性能设备有合理降级；
- 新增代码具有必要测试；
- 全量自动化测试通过；
- 包体审计通过；
- 关键界面已真机截图或录屏确认；
- 文案涉及专业事实时，已确认来源或标记为候选内容。

仅在开发者工具中“看起来能用”，不视为完成。

## 9. 风险与应对

| 风险 | 可能影响 | 应对方式 |
| --- | --- | --- |
| 主包空间仅剩约 96 KB | 新音频、照片和视频导致无法发布 | 媒体上云、懒加载、分包；主包只留必要兜底 |
| 为增强趣味加入过重动效 | 中低端手机卡顿、发热 | 限制并行动画；低性能降级；真机优先验收 |
| 音效过多或重叠 | 嘈杂、延迟、体验反而下降 | 统一音频管理、高频节流、分类音量 |
| 新手难以精确完成操作 | 完成率低、用户挫败 | 方向提示、近目标吸附、可选入门辅助 |
| “游戏化”破坏专业表达 | 非遗内容娱乐化或失真 | 趣味反馈服务于理解，不虚构工艺事实 |
| 外部素材链接失效 | 页面空白、汇报时无法展示 | 转存到项目可控云存储并保留本地占位 |
| 素材授权不清 | 无法公开发布 | 接入前登记来源与使用授权 |
| 需求不断扩展 | 工期失控、核心体验迟迟不稳定 | 新需求按 P0/P1/P2 分类，非核心项进入下一版 |

## 10. 方案 A 的后续验证条件

方案 A 不删除，但必须满足以下条件后再考虑：

1. B+ 版本已完成真机验收；
2. 10 名新手中至少 8 名能独立完成五步；
3. 当前小程序没有阻断性缺陷；
4. 已经明确存在原生小程序无法实现、且对目标用户确有价值的表现需求；
5. 团队能够接受微信小游戏的独立工程、构建、测试和发布链路；
6. 有明确设备性能目标和可承担的长期维护成本。

满足条件后，只做一个 3～5 个工作日的独立技术验证，不直接重写全项目。

验证场景建议只选“打箔”：

- 搭建一个最小 Cocos Creator 微信小游戏工程；
- 实现一次敲击、节奏、粒子、危险状态和完成反馈；
- 在中低端 Android 与 iPhone 上测试帧率、启动时间和包体；
- 与当前原生小程序打箔环节进行用户对比；
- 验证结束后再决定停止、局部独立开发或进入完整方案 A。

方案 A 的工期应单独核算。以有经验的小团队估算，完整实现更接近 14～22 周；个人开发通常需预留约 4～8 个月，不应使用 10～16 周作为无风险承诺。

## 11. 项目决策规则

后续出现新想法时，按以下顺序判断：

1. 是否能提高新手完成率？
2. 是否能让错误原因更清楚？
3. 是否能提升流畅度、真实性或展示质量？
4. 是否会增加主包体积、设备负担或维护复杂度？
5. 是否需要改变微信小程序的技术路线？

前三项收益明确，且第四项成本可控，可进入 B+ 排期；若需要改变技术路线，则进入独立调研或方案 A 验证，不直接并入当前主线。
