## P0-1｜身份错位：全小程序写的是"南京金箔"，不是本项目要做的金箔类非遗

项目简报（`01_项目简报与产品需求/project-brief-v0.1.md` 第15条）明确规定：**在专业访谈锁定具体传承人/城市之前，对外文案必须使用"金箔类非遗项目及其传承人或专业合作对象"这类模糊表述，不得擅自填死认定级别和名称。** 查了 `03_首次专业访谈/` 里的访谈确认表，全是空模板——访谈还没做，人物和城市都没锁定。

但当前代码里，"南京金箔锻制"被直接写死进了5个文件、9处用户可见文案。这些内容来自赵绪成《南京金箔个案研究》和"中国非物质文化遗产网·南京金箔锻制技艺"，是**技术流程的参考资料**，不能当成本项目已确认的身份来用。

## P0-2｜结构断裂：今天新增了一条完全独立、未测试的流程，首页入口指向它，但档案页入口还连着老流程

这是本次代码盘点发现的最大结构问题，**不是历史遗留，是今天（2026-08-09 17:47～20:16）新增/改动的**：

- `miniprogram/pages/craft/`、`miniprogram/pages/foil-apply/`、`miniprogram/pages/foil-result/`、`miniprogram/pages/home/index.js`、`miniprogram/pages/home/index.wxml` 的最后修改时间都是今天下午到晚上。
- `miniprogram/pages/home/index.js` 第39行 `startExperience()` 现在导航到 `/pages/craft/index`（新流程：12步说明 → 单手势贴箔 → 简易结果页，共116行代码，**没有对应的自动化测试**）。
- `miniprogram/pages/archive/index.js` 第42行的 `startExperience` 仍然导航到 `/pages/experience/index`（旧流程：5步交互——做捻子/装家生/打箔/出具检查/切箔成叶，约1036行代码，**218项自动化测试全部覆盖这条线**，含学习报告、收藏、Canvas海报、匿名埋点等完整能力）。

也就是说，现在小程序里事实上**同时存在两条互不相通、内容和交互复杂度完全不同的主线**：从首页进去是今天新写的、简单但没有测试保护的贴箔手势；从"金箔志"档案页进去才是打磨了两周多、有完整数据闭环和测试覆盖的五步体验。用户从首页正常路径根本走不到那套真正成熟的系统。这很可能就是你觉得"结构混乱"的直接原因——不是某个页面做得不好，是App里同时跑着两个不同方向的产品。

**必须先做的决策**（不是Codex能替你做的，需要你或指导老师拍板）：

1. 保留旧的五步 `experience` 流程作为主线，今天新增的 `craft` / `foil-apply` / `foil-result` 三个页面从 `app.json` 移除或明确标记为实验分支，首页 `startExperience` 改回指向 `/pages/experience/index`；**或者**
2. 确认要转向新的"12步阅读 + 单手势贴箔"方向，那么需要：补上 `foil-apply`、`foil-result` 的自动化测试；决定旧的 `experience` 五步系统（含学习报告、收藏、埋点等P1功能）是整体迁移过去还是废弃；同步更新 `docs/当前项目结构与功能清单_20260809.md`（这份文档写于今天14:56，比代码改动早了近3小时，现在已经不准确）。

**在决策之前，不要再让Codex在任一条线上继续叠加新功能**——现在每加一次都是在两条岔路上分别加钱，越往后合并成本越高。

## P1｜PRD版本与实现脱节

`01_项目简报与产品需求/金箔非遗小程序产品需求文档PRD-V0.3.docx` 写的是"3分钟、3步、二选一路线锁定一条"（第4.3节）。现在代码里实际是"5步"（experience流程）或"12步阅读+1手势"（今天的craft流程），且 `data/routes.js` 里两条候选路线（制箔/贴箔）都还在代码里同时保留，没有真正"锁定一条"。

建议：等P0-2的结构决策定下来之后，回头更新PRD到与实现一致的版本号，避免文档和代码继续分岔。这一步不紧急，但决策一旦定了要马上做，否则下一次交接又会出现"文档说3步、代码是5步、现在又冒出12步"的三方矛盾。
