# 候选知识卡与任务地图设计

## 目标

为两条候选路线各提供三张可回看的知识卡，并让既有三步骤体验显示任务地图，形成“阅读候选说明 -> 执行步骤 -> 回看节点”的学习路径。

## 内容边界

- 全部内容为通用候选示例文案，统一标记“候选内测内容，尚待专业确认”。
- 不写历史年代、产地、人物、真实材料配方、真实技法结论或专业认证结论。
- 使用本地静态配置和既有本地占位视觉；不新增 CloudBase 数据、云函数、埋点字段或远程素材。
- 不记录或展示 OpenID、UnionID、设备标识或其他身份信息。

## 知识卡模型

每条配置内候选路线拥有且只拥有三个知识节点，与既有步骤一一对应：

1. `observe`：材料与目标。说明本步骤是候选观察练习，提示用户关注材料、目标和边界。
2. `motion`：动作观察。说明本步骤是候选动作模拟，提示用户关注方向、节奏和反馈。
3. `inspect`：结果检查。说明本步骤是候选检查练习，提示用户关注数字结果、复盘和再次练习。

每张卡包含稳定的 `id`、`routeId`、`stepId`、标题、候选示例说明、观察提示和候选标记。路由、步骤和卡片之间必须严格匹配；未知标识不渲染。

## 页面与交互

### 首页

每条路线卡显示“3 个学习节点”，保持当前路线选择和开始入口。

### 体验页

顶部显示三节点任务地图：已完成、当前、未开始。地图只反映状态机的步骤进度，不引入评分。

每个当前步骤提供“查看本节点说明”入口，在页内展开相应知识卡；关闭后继续体验。步骤切换后，当前卡同步切换。

### 结果页

在学习报告之后显示“回看学习节点”，呈现该路线的三张卡，并按本次报告标记已完成节点。报告不可用时卡片仍可回看，但不显示完成标记。

### 档案页

候选路线卡展开或折叠其三个知识节点，保留收藏、进度和开始体验入口。档案页不会把候选卡作为正式档案结论。

## 数据与错误处理

- 新增一个纯本地静态知识卡模块，并提供按路线、按步骤的只读查询。
- 使用现有步骤状态机与本地学习报告；不改变学习仓储字段和匿名埋点契约。
- 查询不存在、配置错误或页面读取失败时显示安全空状态，不阻断体验、报告、收藏或进度。

## 验收

- 两条路线各渲染三张、共六张严格匹配步骤的候选知识卡。
- 首页显示三个学习节点；体验任务地图随三步骤变化。
- 体验、结果和档案均能回看对应知识卡。
- 卡片与页面始终显示候选内测说明，不出现正式化、专业认证或历史事实断言。
- 现有 `npm test` 仍为零失败，且未新增 CloudBase 或身份字段。
